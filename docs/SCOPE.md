# 范围：做什么，不做什么

2026-10-08 按 0.1.0 的实际代码重写。活文档，决策变了就改这里。

## 一句话

在 Zotero 阅读器里划词，把词加进你选定的墨墨云词本，再送进学习计划。只同步单词。

## 已经做了的

### 划词与加入

划词不等于加入。划词只出弹窗，点「加入」才写；不点就 Esc 或接着划下一个，什么都不留。

用的是官方钩子 `Zotero.Reader.registerEventListener('renderTextSelectionPopup', ...)`，往 Zotero 原生的选中弹窗里追加一块，不自造悬浮窗，也不动它原有的颜色行和高亮按钮。选中的文本从 `params.annotation.text` 来，拿不到时退回读 DOM 选区。

三个状态，界面和代码用同一套说法：

| 状态 | 什么时候进 | 数据在哪 |
|---|---|---|
| 未加入 | 划了词、弹窗开着、还没点 | 哪儿都没有 |
| 已入队 | 点了「加入」 | 本地 JSON 队列，墨墨那边还没有 |
| 已同步 | 后台推送成功 | 墨墨有了，本地记着返回的 id |

选区超过一个词时把词列出来让你点一个。挑中的词再给出词形候选：动词原形和分词形容词在墨墨是两个独立词条（`attenuate` 和 `attenuated`、`limit` 和 `limited`），该背哪个只有读的人知道，所以两个都摆出来让你点，默认选原形。词形只有一种时这一行不占位置。

输入框兜底，候选都不对就直接改。同一个原形不会入队两次。

弹窗里没有设置入口，设置在 Zotero 的设置面板里。

### 后台推送

不在划词那一刻推，走队列。每条记录两步写：

1. 读云词本内容，把原形追加到末尾，整本写回
2. `study/add_words` 把词加进学习计划

两步分别记状态，中间失败算 `partial`，重试只补没成的那步，已经成的不重写。认证失效（401 `common_unauthorized`）暂停整个队列并提示重填 Token，不在阅读中途弹窗。

限速按官方频控：10 秒 20 次、60 秒 40 次、5 小时 2000 次，设置页和后台队列共用一个传输层。**每天 600 条的内容创建配额对本项目不适用** —— 那个池子只计例句、助记、释义，我们一条都不创建。

### 设置

Token、云词本、「加入学习计划」开关、连接测试。Token 不进 Zotero prefs 明文。

云词本在设置页里管：点「查询云词本」列出账号里的全部词本（翻完所有页，排除「我的收藏」），选一个点「使用所选」；或者填个名字点「新建并使用」，插件直接建一个不发布的词本并选上。**存的是词本 id，不是名字** —— 你之后在 App 里改名不影响同步。换词本会先停下正在跑的队列，再恢复。

没选词本时同步不启动，设置页写明「尚未选择云词本，同步不会开始」。

## 明确不做

- **例句**。2026-10-08 砍掉，代码里一处 `phrases` 都没有。砍的路径是：先去掉文献出处，再去掉自动抓整句，最后连例句本身一起去掉
- **文献出处**。作者、年份、DOI、页码、`zotero://` 深链一概不采集、不存储
- **按 Zotero 分类分词本**。固定写一个词本
- **打开文章时提示「这篇有几个你在背的词」**。接口够用（`study/query_study_records` 收 `spellings`，一篇论文 1 到 2 个只读请求就够），但没实现
- 批量回灌历史文献、停用词分级过滤、墨墨记忆卡 Markji

## 已知限制

**词形还原有解不开的歧义**。规则是本地的，不查词典，所以靠拼写分不开的几类会猜错：`bias` 会被当成复数削成 `bia`；`orthogonality` 这类派生形式不还原成 `orthogonal`。所有候选都保留在 `lemmaCandidates()` 里，弹窗那个输入框也能当场改。**根治要在同步时拿候选去 `vocabulary/query` 让词库仲裁**，接口已经备好，还没接。

**弹窗不显示释义**，因为墨墨开放 API 根本不提供（见下面的接口事实）。现在弹窗给的是：选区里的词、还原后的原形、加入状态。

**每个加入的词都会被提前复习**。`advance: true` 写死在同步服务里，设置页没有开关。一次划二十个词，当天复习队列会被插队打乱。

**写词本是整本覆写**。墨墨的 content 是一个大字符串，只能读出来追加再整个写回。同步期间你在 App 里编辑同一个词本，那些改动会被覆盖。一次同步 N 个词就有 N 次覆写窗口。

**吞吐约 6 秒一个词**。每个词 4 个请求（读词本、写词本、查词、加计划），限速器最小间隔 1600 毫秒。划 50 个词要跑 5 分钟。

## 下一步

按价值排：

1. 用词库仲裁收口词形还原的歧义 —— 同步时把候选一起丢给 `vocabulary/query`，取词库认识的那个，词本和学习计划都用它
2. 把 `advance` 做成设置项
3. 补「打开文章提示在背的词」

## 接口事实

路径是 `https://open.maimemo.com/open` + `/api/v1/memo/...`，以官方 OpenAPI 文档为准。2026-09-21 那轮实测用的是不带 `memo` 的旧路径，也能通，但官方文档里没有，不要再用。

**开放 API 拿不到词的释义。** `interpretations`、`notes`、`phrases` 三个接口只返回用户自建的内容，词典自带的释义、助记、例句一条都不给（2026-10-09 实测，`request`、`attenuated` 等词全部返回空数组）。查单词的两个接口也给不出释义：`GET /api/v1/memo/vocabulary?spelling=` 和 `POST /api/v1/memo/vocabulary/query` 返回的都只有 `{id, spelling}`，官方 `Vocabulary` schema 里就只定义了这两个字段，实测也确实只有这两个。所以弹窗里想显示释义，只能接第三方词典，墨墨这边没有这条路。

**词库对变形词的收录没有规律**，不是按语法规则收的，更像按词频。2026-10-09 实测：已词汇化的分词形容词 13/13 有独立词条（limited、advanced、related、attenuated、confounding…），纯时态形式 11 个里有 7 个（asked、measured 有，requested、computed 没有），复数 6 个里有 3 个，派生 5 个里有 4 个。**原形的收录率最稳，所以还原到原形是对的默认**；但 `attenuated` 和 `attenuate` 这种两个都有词条的情况，还原会丢掉你实际读到的那个义项，墨墨把它们当两个词、两张卡。

**已经在学习计划里的词再加一次是安全的**：`add_words` 返回 `added_count: 0`，学习记录完全不变（复习日期、学习次数、上次反馈全部原样）。插件的学习计划网关会走核对分支确认词已在计划里，然后算成功，不会卡在 partial。2026-10-09 用真实账号验过。

新建云词本的 `content` 不能为空。实测传空串返回 400 `notepad_invalid_content`，提示「云词库不存在」，文档里没写这条。插件用一个章节标题 `#Zotero` 占位，建出来的词本不含任何单词。

云词本列表里会混进「我的收藏」，靠 `type` 区分：云词本是 `NOTEPAD`，收藏是 `FAVORITE`。
